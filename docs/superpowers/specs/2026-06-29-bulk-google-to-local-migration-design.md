# Bulk Google→local password migration — design

**Epic:** CorpAdmin-AZ-lmu
**Date:** 2026-06-29
**Status:** design

## Контекст
После отключения Google OAuth (CorpAdmin-AZ-dbo) 442 юзера `@polati.ru` не могут
войти. Вместо ручной работы саппорта — массово проставить им пароли из реестра
`docs/Реестр аккаунтов.xlsx` (лист «Аккаунты GSuite @polati.ru»).

Dry-run (read-only) подтвердил: 442 google-юзера, домен один — `@polati.ru`.

## Источник
Лист `Аккаунты GSuite @polati.ru`, колонки (0-based):
- col2 `Аккаунт GSUite` — email (ключ матчинга)
- col3 `Пароль GSUite` — пароль для установки
- col5 `Уволен` — флаг увольнения

## Матчинг и классификация
Ключ — `lower(strip(email))`, точное совпадение. Категории (по 442 google-юзерам):

| Категория | dry-run | Действие |
|---|---|---|
| settable активный (есть пароль, не уволен) | **414** | ставим пароль + `auth_provider=local` |
| **Уволен** (матч, но уволен) | 18 | **пропускаем**, выдаём список для блокировки |
| пароль пустой в листе | 6 | пропускаем, список → саппорт |
| нет строки в листе | 4 | пропускаем, список → саппорт |
| дубль email с конфликтом паролей | (по факту) | детерминированно: предпочесть строку не-«Уволен» с непустым паролем; если всё ещё ≥2 разных пароля → пропустить, в список конфликтов |

Решения пользователя зафиксированы: уволенным — ничего не ставим (их аккаунты
подлежат блокировке, отдельный шаг); пустой пароль / нет строки «не может быть»,
но если встретится — в список на саппорт; дубли разрулить детерминированно.

## Архитектура (безопасность во главе)
**Хэшируем локально, пишем через SSH-туннель** — плейнтекст-пароли не покидают
рабочую машину и не копируются на прод:
- `passlib CryptContext(schemes=["bcrypt"])` локально → `$2b$12$…` (идентично
  `app/core/security.py`; backend такие хэши принимает — проверено).
- SSH-туннель `ssh -L 15432:localhost:5432 -p 2201 brolin@wgfi2.p4i.ru`, локальный
  psycopg2 → `localhost:15432`, БД `corpweb_db`.
- Guard: пароль >72 байт (лимит bcrypt) — пропустить + флаг (на практике не будет).

Чистые функции (юнит-тестируемы):
- `parse_registry(path, sheet) -> dict[email, list[(pw, fired)]]`
- `resolve(entries) -> (pw|None, fired|None)` — дедуп/конфликт
- `classify(db_emails, registry) -> Categories` (settable / fired / empty / norow / conflict)

Запись:
```sql
UPDATE users SET password_hash=:hash, auth_provider='local', updated_at=now()
WHERE lower(email)=:email AND auth_provider='google';
```
`AND auth_provider='google'` → **идемпотентно**: повторный прогон не трогает уже
мигрированных и не перезатирает локальных юзеров.

## Безопасность
- `docs/Реестр аккаунтов.xlsx` + `docs/*.xlsx` → `.gitignore` (сделано).
- Пароли НЕ логируем, НЕ коммитим, на сервер НЕ копируем. В отчётах — только
  email (маскированный) и длины/категории.
- Скрипт миграции (без секретов) можно коммитить.

## Процедура (порядок критичен)
1. TDD чистых функций (parse/resolve/classify) на синтетике.
2. **Dry-run на проде** через туннель (read-only SELECT google-юзеров) → отчёт:
   точные числа по категориям + список конфликтов/уволенных/manual. Показать юзеру.
3. **Бэкап**: `pg_dump -t users` на проде → файл с timestamp (для отката).
4. **Apply** через туннель в одной транзакции, идемпотентно.
5. **Верификация**: счётчики google→local; spot-check `verify_password` для 3-5
   случайных; counts users=502 без потерь.
6. Список 18 уволенных + 10 manual — отдать юзеру; блокировку уволенных —
   отдельным подтверждённым шагом.

## Out of scope
- Блокировка/удаление уволенных (отдельный шаг с approval; снимет их VPN-peer'ы).
- 10 manual (пустой пароль / нет строки) — саппорт.
- Прочие домены/листы реестра (в БД только `@polati.ru`).

## Testing
Юнит (pytest, синтетический workbook через openpyxl in-memory):
- parse: маппинг колонок, strip/lower email, пустой пароль, отсутствие email.
- resolve: один пароль; дубль одинаковый; дубль-конфликт; уволен+активный дубль.
- classify: settable / fired-skip / empty-skip / norow-skip / conflict-skip; счётчики.
- hash guard: пароль >72 байт пропускается.
Интеграция (dry-run) — фактический отчёт против прод-снимка email'ов.

## Rollback
`pg_dump -t users` восстановить, либо точечно вернуть затронутые id (apply пишет
лог id→old_provider в локальный файл вне git).
